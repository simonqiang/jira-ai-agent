# Week 4 implementation note

Week: 4 — Collect sprint history continuously
Goal: "My sprint data is collected reliably while my local collector is running."
Implementation date: 2026-09-30
Decision: **complete pending pilot-user demo** — all deliverables are implemented,
the full fixture suite passes, and every storage/sync behavior was verified live
against the real Jira project and the local Docker PostgreSQL (evidence below).
The remaining roadmap item is the pilot user's own Friday demo (edit a sandbox
ticket, watch it persist across a collector restart).

## What was built

| Deliverable | Implementation |
|---|---|
| PostgreSQL migrations | `src/scrum_agent/migrations/001_init.sql` + a ~50-line SQL-file runner (`storage/db.py`): `collection_runs`, `issue_snapshots` (tombstone via `deleted_at`), `issue_events` (dedup key `(issue_id, changelog_id, item_index)` — changelog items have no id), `board_config_versions` (sha256 change detection, A→B→A preserved), `ingestion_checkpoints`, and a `collection_freshness` VIEW. CLI: `scrum-agent migrate` (idempotent; verified twice). App tables live in schema `scrum_agent`; ADK owns its own session tables. |
| Persistent ADK sessions | `agent/chat.py`: `build_session_service` swaps `InMemorySessionService` for ADK's `DatabaseSessionService` when `SCRUM_AGENT_DATABASE_URL` is set (DSN rewritten to `postgresql+asyncpg://`); sessions are keyed by app/user/session (single pilot user) and survive restart. Verified live: a session created by one service instance is visible to a fresh instance. Without a database URL, chat behaves exactly as in Week 3. |
| Idempotent collector | `sync/collector.py`: polls `updated >= <last success − 1h overlap>` (cold start: full scope), reconciles every hinted key with an authoritative detail read (curated fields incl. the board's estimate field) plus the full paginated changelog (`iter_issue_changelog`, startAt/isLast, fail-closed like the sprint pager), upserts snapshots, inserts dedup-keyed events, tombstones 404/403 issues (401 aborts the run), versions the board configuration on change, checkpoints only successful runs, and marks stale `running` rows `interrupted`. Bounded `Retry-After` handling for 429. |
| Freshness + credential alarm | `sync/freshness.py` + CLI `collect`/`freshness`: alarms for never-collected, >24 h stale, and expired token (`SCRUM_AGENT_TOKEN_EXPIRES_ON`, because Jira cannot report token expiry — ADR-0001); warnings for expiring-within-7-days tokens and failed/interrupted runs since the last success. `freshness` exits 1 on alarms; `collect --full` forces whole-scope reconciliation. |
| Scheduling | Not configured, per the roadmap's "only if useful": the README documents a crontab/launchd line for `scrum-agent collect`. No webhooks, nothing public — the DB binds to 127.0.0.1. |
| Backups | Documented `pg_dump`/`psql` one-liners through docker compose; restore exercised (below). A second database `scrum_agent_test` is the documented target for the gated DB integration tests. |

## Verification evidence

- Full suite: **302 passed + 1 skipped** (`pytest`; the skip is the gated DB
  round-trip test — it runs too when `SCRUM_AGENT_TEST_DATABASE_URL` points at
  a disposable database, giving **303 passed**), `ruff check .` and
  `ruff format --check .` clean. No live Jira in tests.
- Live run against real Jira (project GACD) and Docker PostgreSQL, 2026-09-30:
  - `migrate` twice → second run applies nothing.
  - Cold-start `collect`: **256 issues, 1,285 changelog events in 4 m 11 s**, no
    rate-limit failures.
  - Delta `collect` → 0 issues/0 events; `collect --full` replay → 256 issues
    re-read, **0 duplicate events** (dedup holds on real data).
  - `kill -9` mid-run → run row stays `running`; next collect marks it
    `interrupted` ("superseded by a newer run") and succeeds; history unchanged.
  - Backup/restore: `pg_dump` → schema dropped → restore → `freshness` healthy
    (256 live issues / 1,285 events intact).
  - Credential alarm: expired date → `ALARM`, exit 1; date in 4 days →
    WARNING, exit 0.
  - ADK `DatabaseSessionService`: session created by one instance found by a
    second instance (tables auto-created in schema `scrum_agent`, no collision
    with collection tables).
- Design notes: psycopg connections run autocommit so partial state from an
  interrupted run is resumable and only the checkpoint marks success; the
  migration runner wraps each file in an explicit transaction (an implicit
  transaction would otherwise turn them into savepoints — caught by the gated
  round-trip test).
