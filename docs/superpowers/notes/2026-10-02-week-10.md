# Week 10 — permission-aware semantic search

Implemented the retrieval stack on top of Week 4's snapshots: ADF-structured
chunking, pgvector embeddings, hybrid retrieval, and the live access/revision
recheck that gates every piece of retrieved text.

## What was built

- **`migrations/005_retrieval.sql`** — `CREATE EXTENSION vector` and
  `scrum_agent.issue_chunks`: one row per chunk with `chunk_kind`
  (`summary`/`description`), `chunk_index`, nearest `heading`, `content`,
  `content_hash`, `source_updated` (the issue's revision at index time),
  `source_url`, `embedding vector` and `embedding_model`. A generated
  `content_tsv` tsvector column plus a GIN index serve full-text; per spec §7
  no approximate (IVFFlat/HNSW) index exists until a benchmark justifies one,
  and queries are always filtered to a single `embedding_model` so vector
  spaces are never mixed.
- **`retrieval/chunking.py`** — walks Atlassian Document Format nodes
  (paragraphs, bullet/ordered/decision/task lists, tables, containers such as
  panels and expands) rather than splitting raw text; each block carries its
  nearest heading. The summary is indexed as its own chunk. Plain-string
  descriptions and over-long blocks are handled (split, never dropped).
- **`retrieval/embeddings.py`** — OpenAI-compatible `/embeddings` client
  (batched, shape-validated, typed `EmbeddingError`). Configured through
  `SCRUM_AGENT_EMBEDDING_MODEL`/`_API_KEY`/`_BASE_URL`; the key falls back to
  the chat model key so the pilot usually configures nothing extra.
- **`retrieval/service.py`** — `RetrievalService.reindex()` chunks+embeds only
  issues whose `updated` revision or embedding model changed and prunes
  tombstoned chunks; `search()` embeds the query, retrieves via
  `PgStorage.hybrid_search` (vector candidates + full-text candidates fused by
  reciprocal rank fusion, best chunk per issue, tombstone-safe join), applies
  a similarity floor so no-match requests abstain, then rechecks.
- **The recheck** — one project-scoped `key in (...)` JQL through the Week 2
  client verifies the whole candidate set against live Jira before any text is
  returned: drifted revision ⇒ `stale`, key not returned ⇒ `revoked_or_deleted`
  (covers revoked access, deletion and out-of-scope keys). Both delete the
  issue's chunks; the excluded source is named with its reason but its text
  never reaches the model or the output.
- **Surfaces** — CLI `scrum-agent reindex` and `scrum-agent related --query …`;
  the read-only chat agent gains `find_related_tickets` (explicitly a
  suggestion, never proof of duplication; structured tools remain the route
  for exact keys and typed filters).

## Verification evidence

- `tests/test_retrieval.py` — chunking (summary separation, heading
  association, table/list rendering, long-block splitting, plain-string
  safety); reindex (full pass, unchanged-skip, changed-issue refresh,
  tombstone pruning); search (issue dedup, single batched recheck query,
  full-text fallback, stale/revoked exclusion + chunk invalidation, no-match
  abstention without a Jira call, blank-query rejection); the 20-case
  development set (10 paraphrases, 2 identifier cases, 4 no-match, 2 stale,
  2 revoked) over an 8-issue corpus with a deterministic embedder.
- `tests/test_storage.py` — 005 migration contract (provenance columns,
  uniqueness, no approximate index) plus a gated round-trip against real
  PostgreSQL/pgvector: chunk replacement, deduped fused ordering, similarity
  read-back, model isolation, delete/prune.
- `tests/test_agent_tools.py` — `find_related_tickets` payload shape,
  config-error translation when retrieval is unavailable, input validation.
- `tests/test_config.py` — embedding settings optional by default, HTTPS-only
  base URL, blank rejection, key fallback, secrets never in repr/dump.
- Full suite green (gated DB tests included against `scrum_agent_test`);
  `ruff check .` and `ruff format --check .` clean.

## Remaining acceptance actions (pilot user)

1. Friday demo: `collect`, `reindex`, then a differently worded query such as
   "customer card charge retry silently fails" surfacing the retry ticket —
   open the cited source links.
2. Configure a real embedding endpoint (`SCRUM_AGENT_EMBEDDING_MODEL` plus
   key; z.ai's OpenAI-compatible endpoint is the default base) and confirm
   real-model similarity beats the development-set floor; re-run `reindex`
   after any model change (rows carry the model, old vectors are simply
   re-embedded on the next pass).
3. Week 11 owns the held-out 50-query evaluation, duplicate-suggestion
   precision and the quality gate; this week's set is the development
   checkpoint.
