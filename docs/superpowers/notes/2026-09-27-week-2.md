## What was built

| Deliverable | Implementation |
|---|---|
| Issue-key lookup, board/sprint selection, typed filters | `src/scrum_agent/search/`: `IssueFilters` (status, assignee incl. `Unassigned`, issue type, labels, sprint, unresolved-only) compiles to quoted JQL — callers never pass raw JQL; `SearchService` resolves sprint IDs/exact names/unique substrings and raises `AmbiguousSprintError` (with candidates) instead of guessing. Client gained `get_sprint` and `iter_board_sprints`. |
| Pagination, bounded requests, actionable errors | Sprint listing follows `startAt`/`isLast` across pages with a `max_pages` bound and rejects malformed/incomplete pages; issue search already followed `nextPageToken` with bounds. 401/403/429 remain typed errors with actionable messages (`Retry-After` honored via `JiraRateLimitedError.retry_after`); no automatic retries. |
| Trusted scope and centralized access checks | `src/scrum_agent/auth/PilotScope` (site, project, board) is the single scope authority. `JiraClient` delegates all issue/board/sprint checks to it and exposes `client.scope`; out-of-scope results fail closed (`JiraPermissionError`), never silently filtered. |
| Checked query set | `tests/checked_queries.py`: `FakeJira` fixture server implementing the real endpoints/pagination contracts, plus 14 checked queries covering empty results, ambiguous/unknown/unique-substring sprint names, multi-page search and sprint listing, cross-project search leakage and cross-board sprints — each denied. |

CLI: `scrum-agent sprints [--state ...]` and `scrum-agent search --sprint
<name-or-id> --type Bug --unresolved ...` implement the Friday demo shape;
ambiguous sprints list candidates on stderr with exit 1; an accurate zero is
printed as "No issues match the query (checked: 0 issues)." with exit 0.
