# Week 7 — drafting tickets from team-standard templates

Implemented versioned YAML templates and deterministic draft generation for
Story, Bug and Task tickets. `scrum_agent/drafting/templates.py` loads
`drafting/ticket_templates/*.yaml` once per process into `TicketTemplate`
models; each template carries its own `version` (`story-v1`, `bug-v1`,
`task-v1`) and each field a `category`: `required_field` (Jira needs it),
`team_policy` (this team always requires it — a Bug's reproduction steps and
verification criteria, a Story's scope and acceptance criteria, a Task's
scope and completion checklist) or `advisory` (an optional writing
suggestion, e.g. dependencies or context).

`drafting/draft.py:build_draft` never invents content: every field either
carries the exact text the caller supplied or, if it is `required_field`/
`team_policy` and missing, becomes an explicit `open_questions` entry.
Missing `advisory` fields become writing suggestions instead and never block
readiness. `ready` is true only once every `required_field` and
`team_policy` field is filled. Two new read-only ADK tools expose this:
`list_draft_templates` (fields + categories, so the model knows what to ask
for) and `draft_ticket(issue_type, fields)` (renders the draft; makes zero
Jira/HTTP calls — verified in tests). `get_template` requires an exact
(case-insensitive) issue-type match, never a fuzzy guess, so a mistyped type
cannot silently apply the wrong team policy.

The agent instruction was extended with a "Drafting tickets" section: only
pass a field's text if the user actually said it, ask the returned
`open_questions` verbatim for gaps, never present a draft as ready until
`ready` is true, and re-call `draft_ticket` with combined fields so answers
accumulate instead of resetting the draft.

## Verification evidence

- `tests/test_drafting.py`: one complete and one incomplete example per issue
  type (six total, mirroring the gaps noted in `docs/samples/*.example.md`),
  template-loading validation (duplicate field keys, a `required_field`/
  `team_policy` field without a `question`, duplicate issue types), advisory
  gaps confirmed non-blocking, unknown fields ignored rather than erroring.
- `tests/test_agent_tools.py`: `list_draft_templates`/`draft_ticket` added to
  the read-only tool registry check; `draft_ticket` asserted to make zero
  HTTP requests; incomplete input returns `open_questions` instead of
  invented content; an unknown issue type returns `invalid_input`.
- Full suite green (`pytest`), `ruff check .` and `ruff format --check .`
  clean.
