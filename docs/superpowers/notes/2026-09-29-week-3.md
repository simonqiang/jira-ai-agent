## What was built

| Deliverable | Implementation |
|---|---|
| Conversation execution | `src/scrum_agent/agent/chat.py`: `ChatService.run_turn` drives the ADK runner per browser session, returning `TurnResult` with server-collected sources and a usage delta; failed runs produce a clear task outcome without invented usage (`usage.py` keeps absent provider metadata at zero, never negative). |
| Cost baseline runner | `src/scrum_agent/agent/baseline.py`: `run_baseline` runs each checked intent in a fresh session and writes a sanitized JSON artifact (model/provider metadata, per-task answer status, calls/tokens/cost-or-`null`, totals) under `docs/superpowers/notes/` by default; unsafe output paths are rejected. CLI: `scrum-agent baseline`. |
| Local chat UI | `src/scrum_agent/web/` + `scrum-agent serve`: FastAPI + Jinja + HTMX on loopback only, with Host/Origin allowlist middleware, HttpOnly/SameSite cookies, in-process short-lived conversations, and source links built exclusively from server-verified `TurnResult.sources`. |
| Chat UI enhancement round | Composer now **clears and refocuses after each send**; an animated "thinking…" indicator (pulsing dots) shows while the turn runs; the Ask button is disabled in flight (no double submits); new turns fade/slide in; the page auto-scrolls to the newest answer; failed requests surface a red error banner instead of doing nothing; the footer session-usage line updates live after every turn via an HTMX out-of-band swap. All motion respects `prefers-reduced-motion`. |
| Project guide | Lean `CLAUDE.md` at the repo root (commands, layout, conventions only) so coding agents skip rediscovery each session. |
