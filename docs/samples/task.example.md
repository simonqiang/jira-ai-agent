# Task example (anonymized)

> Derived from a real pilot-project ticket (fetched 2026-09-27), paraphrased and
> anonymized: keys, people and team names replaced. Original mapping kept out of
> the repository.

- Issue type: Task · Status when captured: New · Estimate: **none recorded**
- Requestor: Requesting Team (analytics function)

## Content

Title: Integrate AI demographic analysis to support targeted marketing campaigns

Objective:
Provide AI-generated insights from customer demographic data (age band, region and
similar attributes) that the marketing function can use to design targeted campaigns.

Context:
Marketing analysts currently segment audiences manually; the request asks for an
AI-supported analysis integrated into the existing customer-profile view.

Process scope: reporting, visibility, set-up, onboarding.
Geo scope: all regions.

In scope:
- AI-driven analysis of customer demographic attributes
- Insights surfaced as customer-segmentation suggestions
- Integration into the existing customer-profile surface

Out of scope:
- Campaign execution itself
- New data collection beyond existing profile attributes

Deliverables: analysis capability + segmentation insights in the profile view.
Dependencies: none recorded.
Completion checklist: **not present in the source ticket** (noted as a gap).

## Observations (for Week 7 templates)

- Good: explicit requestor, process scope and geo scope (this team's house style —
  worth capturing as a Task-template section); clean in/out-of-scope split.
- Gaps: **no completion checklist, no dependencies, no estimate**; success criteria
  are implied by deliverables but never stated as checks.
- Structure worth keeping as the Task default: Objective → Context → Scope (process/
  geo, in/out) → Deliverables → Dependencies → Completion checklist.
